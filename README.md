# 3DAngen

Генератор мультяшных 3D-сцен и видео из них — без движков, сборщиков и интернета.

Каждая сцена — **один HTML-файл**: three.js вшит внутрь, тоon-шейдинг с контурами,
свои материалы и анимация на JS. Из любой сцены можно **покадрово отрендерить видео**
(headless Chromium + WebSocket + ffmpeg) — кадр в кадр, без потери ритма и без записи экрана.

```
src/<сцена>/index.html  --build.py-->  dist/<сцена>.html   (открыть в браузере)
                                              |
                                        render.py (CDP + WS)
                                              v
                                     frames/f_000.jpg ...
                                              |
                                        encode.py (ffmpeg)
                                              v
                                        dist/video.mp4
```

## Демо-сцены

| Сцена | Что это |
|---|---|
| `gas-stove` | Мультяшная кухня с газовой плитой: 4 горелки, разноцветное пламя, день/вечер |
| `mascot` | 3D-маскот (персонаж-косяк) на подиуме: toon-шейдинг, дым, авто-вращение |
| `mascot-on-stove` | Маскот ходит по варочной панели и танцует + кинематографичная камера (6 планов) |

`examples/poster.jpg` — кадр из 5-секундного ролика, собранного этим пайплайном.

## Быстрый старт

```bash
# 1. собрать однофайловые версии сцен
python tools/build.py

# 2. открыть сцену в браузере (просто файл, работает офлайн)
#    dist/mascot-on-stove.html

# 3. отрендерить 5 секунд в 30 fps
python tools/render.py dist/mascot-on-stove.html --fps 30 --sec 5

# 4. собрать видео
python tools/encode.py --frames frames --out dist/video.mp4 --fps 30
```

Ключи рендера: `--fps`, `--sec`, `--w/--h` (по умолчанию 1280×720), `--out`,
`--ws-port`, `--debug-port`, `--timeout`.

## Требования

- **Python 3.10+**, `pip install -r requirements.txt` (нужен только `websockets`)
- **ffmpeg** в `PATH` (для `encode.py`)
- **Chromium-браузер**: Edge, Chrome, Brave или Chromium.
  Скрипт перебирает установленные и берёт первый, который отдаёт DevTools-порт
  (корпоративные политики иногда отключают remote debugging — тогда берётся следующий).
  Свой путь можно задать через `CHROME_PATH`.

Никаких npm-пакетов, сборщиков и CDN: three.js лежит в `vendor/three.min.js` (r158, UMD).

## Управление в сценах

- мышь — вращение, колесо — зум
- `mascot-on-stove`: `W` ходит, `D` танцует, `S` стоит; клик по горелке — огонь,
  `1`–`4` — горелки, `A` — все, `R` — погасить, «День/Вечер» — свет
- `mascot`: клик по персонажу — «затяжка», `R` — авто-вращение, `S` — дым
- у каждой сцены своя панель управления внизу

## Структура

```
vendor/three.min.js      three.js r158 (UMD), вшивается в каждую сцену
src/<сцена>/index.html   исходник сцены с маркером /*__THREE__*/
dist/<сцена>.html        собранная однофайловая версия (можно открывать напрямую)
tools/build.py           инлайн three.js -> dist
tools/render.py          покадровый рендер (CDP + WebSocket-приёмник кадров)
tools/encode.py          кадры -> mp4 (ffmpeg), опционально gif
docs/pipeline.md         как это устроено внутри и как добавить свою сцену
```
