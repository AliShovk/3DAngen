# Пайплайн 3DAngen

## 1. Сцена (`src/<name>/index.html`)

Обычный HTML-файл, внутри — один `<script>/*__THREE__*/</script>` (заглушка под
библиотеку) и `<script>` с кодом сцены. Никаких импортов и сборщиков: three.js
подключается глобальным `THREE` после сборки.

Общие приёмы, на которых построены демо-сцены:

- **toon-шейдинг**: `MeshToonMaterial` + `DataTexture`-градиент из 4 ступеней
  (`toonRamp()` / `toon(color)`).
- **контуры**: второй меш с тем же `geometry`, материал `BackSide`, вершины
  сдвинуты по нормали — inverted hull (`OUTLINE_MAT`). Толщина задаётся в
  локальных единицах, поэтому для мелких объектов (маскот) используется
  отдельный материал с большим сдвигом.
- **процедурные текстуры**: почти всё рисуется в canvas (бумага, плитка,
  шахматный пол, блики, дым) — внешних ассетов нет.
- **свет**: hemisphere + key/spot с тенями + точечные источники для пламени;
  переход «день/вечер» — лерп интенсивностей, цвета света и `exposure`.

## 2. Сборка (`tools/build.py`)

Берёт `vendor/three.min.js`, подставляет вместо маркера `/*__THREE__*/`,
проверяет, что внешних `<script src=...>` не осталось, кладёт результат в
`dist/<name>.html`. Итог — до ~700 КБ на сцену, открывается двойным кликом,
работает без сети.

## 3. Рендер кадров (`tools/render.py`)

Ключевая идея: **не записывать экран и не полагаться на `requestAnimationFrame`**
(его частота зависит от нагрузки), а прогонять таймлайн вручную.

Сцена умеет режим `?frames=1`:

```js
// сцена: фиксированный шаг, никакой зависимости от fps
for (let f = 0; f < total; f++){
  const target = f / fps;                 // время кадра
  while (t < target - 1e-6){ stepFrame(dt); t += dt; }   // dt = 1/120
  time = target;
  cineCam(time);                          // камера по раскадровке
  renderer.render(scene, camera);
  WS.send('FRAME ' + f + ' ' + canvas.toDataURL('image/jpeg', .92));
}
```

`render.py` при этом:

1. поднимает WebSocket-сервер (`FrameSink`) на свободном порту;
2. запускает `--headless=new` браузер с `--remote-debugging-port`, перебирая
   Edge → Chrome → Brave (первый, у кого реально поднялся CDP);
3. через CDP открывает `file:///.../dist/<scene>.html?frames=1&fps=..&sec=..&port=..&w=..&h=..`;
4. ждёт, пока `document.title` станет `FRAMES_DONE` (сцена сама сообщает статус:
   `WS_INIT` → `FR_<i>` → `FRAMES_DONE`);
5. принимает кадры `FRAME <i> data:image/jpeg;base64,...` и пишет `frames/f_<i>.jpg`;
6. гасит браузер и печатает, сколько кадров пришло из ожидаемых.

Почему WebSocket, а не `fetch`/запись файлов: страница открыта по `file://`,
у неё origin `null` — POST на localhost режется CORS/PNA, а WebSocket проходит.
Плюс так кадр уходит одним сообщением без base64-обёрток в JSON.

Параметры кадра (`w`, `h`, `fps`, `sec`, `port`) сцена читает из query-строки,
поэтому один и тот же файл годится и для интерактива, и для рендера.

## 4. Сборка видео (`tools/encode.py`)

`ffmpeg -f image2 -framerate <fps> -i frames/f_%03d.jpg -c:v libx264 -pix_fmt yuv420p
-movflags +faststart`. `--gif` дополнительно собирает палитровый GIF.

## Раскадровка и «смена ракурса»

В `mascot-on-stove` камера описана массивом `SHOTS`:

```js
{t0: 0.00, t1: 0.95, a0: .88, a1: .44, p0: 1.20, p1: 1.14, r0: 2.45, r1: 2.05, y0: .88, y1: .96}
//  время  |  азимут    | полярный угол | радиус      | высота цели
```

`cineCam(t)` находит шот по времени, интерполирует параметры со сглаживанием
(`smoothstep`) и ставит камеру напрямую, без демпфирования — так каждый кадр
детерминирован. Склейки между шотами — резкие, внутри шота — плавный проезд.

Важно: камера в этой сцене должна оставаться в передней полусфере
(`|az| ≲ 1.1`), иначе она уходит за стену кухни и кадр перекрывается геометрией.

## Как добавить свою сцену

1. `mkdir src/my-scene`, скопируйте любую демо-сцену как болванку, оставьте
   маркер `/*__THREE__*/` на месте `<script>`.
2. Для видео добавьте в конец кода `?frames=1`-ветку: `renderFrames(fps, sec)`
   из `src/mascot-on-stove` (шаг `dt`, отправка кадра по WS) — этого достаточно.
3. `python tools/build.py my-scene && python tools/render.py dist/my-scene.html`.

## Если что-то не работает

| Симптом | Причина / что делать |
|---|---|
| `CDP не поднялся` | Политика организации запрещает remote debugging в этом браузере — скрипт перейдёт к следующему; можно задать `CHROME_PATH` |
| Кадров 0, `WS_FAIL` | Порт занят или сцена не собрана; проверьте `--ws-port` |
| Пустой/чёрный кадр | WebGL недоступен в headless: добавлен `--enable-unsafe-swiftshader`; на слабых машинах рендер идёт на CPU — увеличьте `--timeout` |
| Медленно | Уменьшите `--w/--h`, поставьте `--fps 24`, или рендерите на машине с GPU |
| Рваное движение | Не используйте запись экрана/`captureStream` — только покадровый режим, он и даёт стабильные 30 fps |
